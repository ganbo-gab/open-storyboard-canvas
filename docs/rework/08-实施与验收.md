## 已落地的主要路径

- 应用导航：开始创作、生成工作台、画布项目、资产库、提示词库、创作助手；首页、工作台与资产库在 1188px 和 960px 桌面宽度实机检查，无水平文档溢出。
- 工作台：会话、图片/视频/音频/文本模型选择、渠道声明参数、素材引用、生成卡片、停止等待与恢复查询、重新编辑、结果登记资产、发送到指定画布。旧会话异步恢复完成前不写默认模型；重新编辑不携带旧 conversationId。
- 渠道 v2：模板或 AI 文档配置、配置导入、共享请求渲染器、脱敏请求预览。只发送配置模板声明字段；未知提交不自动重发。聊天工具调用真实经过渠道执行路径。
- ComfyUI：节点输入映射、输出选择、依赖预检；待恢复任务保留工作流/地址/绑定快照，不因之后的配置编辑失效。
- 外部 Agent：原有回环 broker + MCP 安全架构保留。配置结构化预览、备份、接入、撤销；稳定描述文件每次请求重读。浏览器明确只读，不能假装安装本机 CLI。
- 画布：左侧节点工具、底部导航、命令搜索；图片/视频浮动输入框使用恒定屏幕尺寸，避边、避底栏；数量菜单、模型选择、`/` 功能和 `@` 引用菜单适配浮层。低缩放时简化节点渲染。React Flow 负责即时变换，普通平移不再逐帧广播整图 store；被动尺寸测量不消耗撤销历史。
- 画布生成应用层：`application/generation` 在调用时读取完整图数据，图片批量、视频任务、流式文本、音频与分镜/全景请求不依赖节点组件挂载。`generation.submit` 直接调用服务，不再广播节点触发事件；旧节点按钮与工具栏的逐项接线由 UI 切换负责。预览与提交共用请求组装；流式连接断开且尚未收到内容时，不把有歧义的请求自动重发为非流式请求。
- 舞台：导演台与预演台共用一套布局——顶栏（返回、工程弹层、模式切换、撤销/重做、截图、录制、面板、Agent、保存）、视口左侧竖向工具栏（选择 V、移动 G、旋转 R、缩放 T、姿态、路径、添加/镜头/动作库/灯光弹层）、右侧停靠面板（图层大纲 + 统一属性检查器 / 截图）、预演台时间轴在视口下方占位而不覆盖。面板挤压视口，场景尺寸由 ResizeObserver 驱动。数值字段可拖动字母微调；Esc 逐层退出且不离开舞台；截图为闪白 + 提示条。场景底色/网格/选中环统一为石墨色系，颜色经显式线性化，不受 photo-sphere-viewer 全局关闭 `ColorManagement` 的影响。对象、机位、轨迹、片段、关键帧仍通过共享命令层编辑与撤销。
- Agent：复用 SDK Runner，home / canvas / stage 作用域隔离；应用生命周期会话保留运行与审批，收起抽屉不等于停止。读工具自动继续；编辑与付费操作受审批约束。已批准工具按原始参数指纹恢复，长分镜方案通过持久 planId 传递，避免日志脱敏破坏内容。

## 持久化不变量与回归

1. 浏览器画布项目逐项目写 IndexedDB。旧 localStorage 项目在事务提交后，原始 envelope 再完整归档到 IndexedDB metadata，归档成功且旧值未被并发修改后才删除原 key。已迁移版本留下的旧 envelope 同样归档、释放配额；归档失败保留原文，已提交项目不降级丢失。
2. 工作台/资产二进制写 IndexedDB，先提交字节再返回稳定引用；同一来源单飞复用，内容哈希避免跨缓存/重载重复存储。显示 URL 延迟创建，引用修改有并发保护。
3. 已成功浏览器任务恢复与轮询共用媒体 hydration。过期 blob URL 只能在 IndexedDB 字节恢复后作为成功结果发布。活跃提交不进入“应用曾关闭”的恢复分支。
4. 未占用预算的免费工具完成/释放不写预算账本；真正付费预占在持久化失败时仍拒绝继续，不能靠吞掉异常绕过限制。
5. 恢复只查原任务，不重新提交；工作台停止等待不宣称取消上游生成，暂停后可恢复查询。

### 500 节点缩放专项复测（2026-10-25）

旧的一次性脚本已删除，`scripts/` 中没有性能 harness；因此重建相同的“可信鼠标输入 + rAF 间隔”采样，不把新场景数值冒充为上表原始录制的重放。使用现有 `localhost:1420`、headless Chromium **148.0.7778.96**、1440×900 / DPR 1、独立浏览器 context。通过真实 `createProject`、`addNodesBatch`、`setCanvasData` 和导航 API 创建临时项目：250 个图片节点 + 250 个文本节点，25×20 网格，间距 360×260、节点 320×220；400 条 `i → i+25` 连线。适应全图后初始缩放 0.154148。每项采样 6 秒，未启用 trace；另开 trace/CPU profile 分析。轮询发送目标间隔为 16.67 ms，但等待 CDP 鼠标确认后实际约 180 次 / 6 秒；不能据此声称已证明每秒 60 次输入/视口提交。

平移为 ±2px、每 30 次反向；连续缩放为 Ctrl+wheel ±1.5、每 12 次反向；极端跳变为 Ctrl+wheel ±1200、每 5 次反向，应用自身将单步倍率限制为 1.6，跨过 0.4 LOD 阈值。以下每格顺序为 **平均帧时 / P50 / P95 / 平均帧率**，帧时单位 ms：

| 操作 | 修改前 | 修改后 |
|---|---|---|
| 稳态空闲 | 16.710 / 16.700 / 17.600 / 59.843 fps | 16.672 / 16.700 / 18.600 / 59.980 fps |
| 全图可见，小幅连续平移 | 16.667 / 16.700 / 17.700 / 60.000 fps | 16.713 / 16.700 / 18.500 / 59.833 fps |
| 全图可见，连续往返缩放 | 16.761 / 16.700 / 17.700 / 59.662 fps | 16.765 / 16.700 / 18.600 / 59.649 fps |
| 连续极端缩放跳变 | 26.739 / 16.700 / 84.300 / 37.399 fps | 16.755 / 16.700 / 18.600 / 59.685 fps |

实际修复的是跨 LOD / 可见性边界的重挂载和继承样式失效风暴：缩放期间只保留**原本已全部挂载**的远景图，不为了优化而主动挂载画外节点；已经进入远景的未选中节点保持低细节，选中节点与组节点沿用完整交互。始终停留在近景的缩放不会额外卸载编辑器或媒体播放器。缩放停止 120ms 后先恢复可见性裁剪，再隔两帧解除低细节覆盖并恢复精确的反向缩放 CSS 变量。缩放中标题/把手不再逐帧维持恒定屏幕尺寸，静止后恢复原样；没有删节点、隐藏连线、降低静止细节或修改图数据来获得帧率。

极端跳变 6 秒内，样式重算由 **470.8ms → 13.0ms**，脚本由 **2739.5ms → 805.7ms**；掉帧间隔（>25ms）由 **39 → 2**。单独检查从 15.4% 放大到 161.6% 后释放：恢复到 **10 个完整节点 / 13 条线**，`keepAllNodesRendered=false`、`simplifyNodes=false`、CSS 比例 **0.6187**；包含输入与释放的 1 秒样本最大间隔 **33.4ms**，没有把原来的 184–200ms 长停顿整体移到释放时。

**严格的“连续缩放平均 ≥60fps”仍未达成，不签硬验收。** 新连续缩放样本 359 帧中仍有 2 个 >25ms 间隔；独立 trace 的主要剩余成本为 Chromium `Layerize` **381.3ms / 3 秒**（样式重算仅 6.8ms）。最长 rAF 回调 **29.4ms**，其中 React 调度/同步工作回调 23.3ms，手势回调 6.1ms；不是所有节点逐帧 React 重绘的证据。单独试验 compositor promotion、layout/style containment、去浮层 blur 未稳定改善，因此这些试验未留在产品代码中。不能把约 59.65 四舍五入为“已稳定 60”。

本切片回归：2 个 Vitest 文件、10 个测试通过（包含近景编辑器/媒体不被额外卸载的边界）；`tsc --noEmit -p .` 的本切片文件 0 个诊断，整仓检查仍因其他并行改动的诊断退出 1，未将其记为整仓通过。每轮临时项目均通过真实删除 API 清理，并查询持久层确认不存在；临时 harness 已删除。原始样本、trace、CPU profile 与截图保留在 `/tmp/canvas-zoom-*`，不作为运行依赖。

**这不是产品修复已经落地，也不是 N4 达标。** 本次只改私有诊断页面，未改产品 JSX/CSS；clean B 仍约 47FPS／P95 50ms，且当前因果样本只覆盖单节点拖动，不能外推百节点拖动与框选。正式视觉实施仍由既定负责人在恢复授权后执行。

建议按以下顺序实施：

1. **直接产生有界 guide 几何。** 保留 `AlignmentGuidesOverlay`、`ViewportPortal`、alignment store 与 snapping/finalizer。仅让竖线 y 端点、横线 x 端点由当前实际 Flow `transform/width/height` 求得；CSSpx 余量除以 zoom 转成 flow-space。必要时与旧绘制区间取交集，空交集不产生反向线段。约束的是线段跨度，不限制合法节点的绝对坐标。
2. **明确相位契约。** 当前 markup 的父 DIV 用 CSS translate/scale，SVG user-space 虚线周期按 `4+3=7`；新起点相对旧起点向外取整至整数周期，旧起点只作相位参考。不要把诊断固定 70、`7/zoom`、UA 分支或 MutationObserver 搬入产品。周期必须与现有 dash 样式保持单一明确契约。
3. **局部订阅。** 活跃 guides 的子组件只关注 guide 坐标与 live Flow 的 pan/zoom/width/height；无关 nodes publication 不应重算范围，不读取持久化 viewport，不逐帧扫描图/DOM。拖动 auto-pan、zoom、resize 也必须更新，不只在 drag start 缓存。
4. **先过视觉/行为门槛。** 保持线宽、颜色、虚线、pointer-events、z-order 与 release/cancel/blur/unmount；hold 不清线。覆盖支持的 `.1–8`、非特殊比例 `.37/1.25`、小数 pan、负/大坐标、两方向、DPR1/2 与连续 resize。独立静态校准中两个 WebKit 的 user-space 方案在所测非特殊比例逐像素一致；Chromium 有非零差异，性质尚未定位，不能称不可见或擅自放宽阈值，须由视觉负责人检查局部原/新/差分图后明确接受。
5. **再验全路径性能。** 对实际 Tauri/system WKWebView 与 Chromium 分别做完整场景、三种负载的独立重复测量；保留真实输入、有效 frame 样本、350/350 解码与所有行为断言。硬门槛仍为 FPS≥50 且帧间隔 P95≤25ms。系统 WK 静态 SVG 校准成功不等于完整图 FPS；当前完整图 WebKit prepare/命中求值尚未取得有效采样，不能签收。
6. **只按剩余证据继续优化。** 有界场景另采 diagnostic trace，不混进 clean 数据；优先分析长间隔内的 Layerize/HitTest/GPUTask 与真实 publication，而不是把平均 FPS 推成根因。保留现有同步 canonical→Flow、引用复用与 geometry/body 分离；不先上异步镜像、sharedSVG 或换引擎。

已关闭当前修复候选：d 相等写入去重（零治疗量）、拖动节点/两条边 will-change（确实改变层但无收益）、workspace 入场 fill 消融（effect 已取消但无稳定收益）。不把这些阴性分支夹带进产品改动。

全图截图的额外边界：固定姿态隐藏 guide 的 visibility／opacity 正控制也未检出像素变化，所以“全图原/新截图相同”不单独证明可见虚线相位；相位结论来自带有效正控制的独立静态场景。系统 WK 本次 `getScreenCTM` 未反映 CSS 父级缩放，其两个数学分支实际端点相同，不当作独立假说比较，也不作为生产 bounds/phase 的比例来源。
