# 03 · 画布交互规格

> 依据：AIGC 需求文档 B/C/D 节（`AIGC/开发文档/01-产品需求总集.md`）、LibTV 10-15 逆向 + 10-17 实地差量（`AIGC/开发文档/实地采集-20261017/libtv.md`）、现有实现审计。截图引用均在该采集目录下。

> 状态边界：用户继续暂停前端实现与Opus调度。按最新日常目标，1000节点工程在正常zoom .6/1.0下的平移/缩放和拖1/5/10已通过当前Chromium/Metal验证（6会话30动作，约60FPS、最差P9518.7ms）；未改产品原有viewport裁剪。旧fit-all/百拖压力未过结果单列，不再作为当前日常门槛，也不冒充完整原生/Tauri通过。其他未验收界面目标继续保留。

## 1. LibTV 的痛点 → 我们的做法

| LibTV 实测痛点 | 我们的做法 |
|---|---|
| 浮动生成器水平居中于节点、不夹边，节点靠边时输入框和生成按钮被裁出屏幕（`libtv/06-node-selected.png`，x=-167） | 浮层**避让定位**：优先节点下方 → 空间不够翻到上方 → 仍不够贴视口底部居中停靠；始终完整可见 |
| 顶部编辑工具条宽 1093，比视口还宽 | 工具条最大宽 = 视口 − 32px，放不下的动作收进「更多」；动作按使用频率排序 |
| 连接点 0×0、仅 hover 显形，拖了半天连不上 | 悬停节点即显示左右 ⊕（屏幕 20px，命中 36px）；拖线时目标节点**整卡**都是落点；⌘L 连接选中的两个节点 |
| 底部 dock 与节点下方浮出的生成器抢同一块区域 | 工具条放**左侧竖排**（同需求 B-01），底部留给生成器 |
| 菜单宽 220/240/340、条目 32/36、圆角 12/16 混用 | 一个 Menu 组件：宽 240、条目 32、圆角 10、分组标题、右侧快捷键 |
| 右键菜单「突然出现」，可发现性差 | 右键菜单与节点标题栏「⋯」按钮是同一份菜单；首次右键给一次轻提示 |
| 标题栏显示像素 `2048 × 1152`，看不出比例 | 显示「16:9 · 2K」（需求 B-18），悬停显示像素 |
| 打开项目新开标签、首次进入 26% 极小缩放 | 同窗口打开；恢复上次视口，首次打开自动「适合屏幕」 |
| 复制粘贴语义混乱 | 双体系严格分离（需求 B-06，见 §6） |
| 首页营销位过载 | 不做商业位 |

LibTV 值得保留的：贴节点的浮动生成器、按节点类型分化的编辑工具条、连线剪刀按钮、多选浮动工具条、`@` 引用节点并编号、`/` 唤起 skill、缩放预设 + 可输入比例。

## 3. 画布引擎

| 输入 | 选择模式 V（默认） | 抓手模式 H |
|---|---|---|
| 左键单击 | 选中 | — |
| 左键拖空白 | 框选 | 平移 |
| 左键拖节点 | 移动（Alt 拖 = 复制） | 平移 |
| 空格 + 拖 / 中键拖 | 平移 | 平移 |
| 触控板双指 | 平移 | 平移 |
| 触控板捏合 / ⌘ + 滚轮 | 缩放（以指针为中心） | 同左 |
| 鼠标滚轮 | 缩放（设置可改为平移） | 同左 |
| 双击空白 | 添加节点菜单（在该位置） | — |
| 右键 | 上下文菜单 | 上下文菜单 |

- 自动识别触控板与鼠标（`deltaMode` + 增量特征），无需用户设置；设置页可覆盖。
- 节点随画布缩放；**标题栏、⊕、浮动生成器、工具条用屏幕空间恒定大小**（需求 C-01）。
- 网格吸附开启时移动吸附 16px；对齐参考线吸附邻近可见节点的边缘/中心（6 屏幕像素阈值，参考线坐标保留为画布坐标）。拖动中按住 ⌘（macOS）/ Ctrl（Windows/Linux）临时关闭对齐吸附，松开立即恢复；Alt 拖动仍为复制，复制节点也参与吸附，原节点保持原位。
- 性能：只渲染视口内节点；缩放 < 40% 时节点降级为缩略图卡（不挂载编辑器、不播视频）；媒体一律用缩略图，原图仅在查看器加载。目标：500 节点 + 400 连线拖动/缩放 60fps。
- 对齐候选空间索引每次拖动建立一次；每帧最多返回 96 个邻近候选、查询 256 个网格单元，不重复遍历 500/1000 节点。拖动各帧仍写回规范 Store；结束或失焦立即清空参考线。
- 多结果堆栈以节点 `batchId`、`batchIndex`、`batchPrimary`、`batchCollapsed` 持久保存；`hidden` 仅由堆栈元数据派生。收起保留所有节点与连线，次要成员不参与框选、整理布局或批量下载；`canvas.query` 仍返回它们并标注 `hidden` / `visibility`。切换主结果、展开/收起各是一条可撤销命令；删除主结果按批次顺序循环提升下一成员。画布内容树包含完整成员，定位次要成员前先设为主结果。
- 自动保存忽略**仅节点 `selected` 改变**的更新，项目重开原本就会清空节点选择；其余字段仍参与保存判断，包括不会增加 numeric revision 的尺寸测量。不能仅凭 revision 或 history 未变化跳过保存，不延迟规范 Store／React Flow 的同步发布，也不把序列化统一挪到手势释放后。

## 4. 节点

### 4.1 类型（合并旧版 17 种）

| 新类型 | 合并自（旧） | 说明 |
|---|---|---|
| 文本 text | aiText、textAnnotation、jsonCard | 富文本；可作为提示词片段被 @ |
| 图片 image | upload、imageEdit、exportImage、panorama | 有图即「素材」，带生成配置即可「生成」；全景图带 `720` 徽标 |
| 视频 video | aiVideo、video | 同上 |
| 音频 audio | aiAudio、audio | 同上 |
| 舞台 stage | blueprint | 导演台/预演台入口（05） |
| 分镜组 storyboard | storyboardSplit、storyboardGen | 宫格切分结果 / 多镜头组，可整体生成 |
| 组 group | group、tag、tagGroup | 颜色、标题、整组执行；标签改为节点颜色 + 文字标签 |

旧项目由迁移器逐类型映射，迁移测试覆盖每种旧类型。

### 4.2 节点外壳

- 卡片圆角 12；标题栏在卡片上方（图标 + 名称 + 「16:9 · 2K」+ 状态），双击改名。
- 悬停：左右 ⊕ 显形、右上「⋯」（= 右键菜单）、生成完成的结果出现下载钮。
- 四角拖拽改尺寸（需求 C-02），保持媒体比例，Shift 自由。
- 生成中：结果区显示进度百分比 + 右上计时器（精确到 0.1s，需求 C-03）；失败反馈按下述结构化分类呈现，一键重试仍是需显式操作与付费授权的视觉规格（C-07）。
- 多结果：主图 + 右上「N」角标，点开展开为结果条，可设为主图/单独下载/拆成节点（C-05）。
- 应用层失败契约：`generation.status` 的 `output.value.failure` 为 `null` 或 `{ category: 'input_moderation' | 'output_moderation' | 'error', retryable: boolean, moderation: boolean }`，节点持久字段为 `generationFailure`。已成功状态返回 `failure: null`；其他状态即使残留错误也只有明确 `failed` 才可能给出 `retryable: true`，不能把 `unknown` / `recoverable_wait` 当作可重提。
- 分类优先使用供应商结构化 `failure_reason/failureReason/reason/code/category`，兼容嵌套错误、Error cause、已保存 JSON 与旧纯文本错误；不检查提示词、配置或凭据字段来猜分类。明确输入/输出审核分别保留方向；只知内容审核但方向未知时为 `{ category: 'error', retryable: false, moderation: true }`，不得猜输入或输出。所有审核失败均 `retryable: false`；其他错误只在供应商明确提供可重试证据时为 true，HTTP 状态码或“临时错误”措辞本身不授予重试权限。诊断沿用凭据、签名 URL 与媒体正文脱敏。
- `retryable` 只用于提示用户是否可显式发起新的尝试，绝不触发付费自动重试。状态查询与恢复只引用原 `jobId` / 原节点，不清除来源、结果引用或历史来伪装新成功。

### 4.3 选中后的浮层

选中单个节点出现两个浮层（屏幕空间）：

1. **编辑工具条**（节点上方）：按类型分化。图片：人像质感 · 全景 · 多角度 · 打光 · 九宫格 · 高清 · 宫格切分 · 标注 · 旋转 · 下载 · 预览 · 删除（需求 D1）；放不下收进「更多」。
2. **生成器 Composer**（节点下方，宽 640）：参考素材条（左接素材自动在列，按 图1/图2、视1、音1 独立编号）· 提示词编辑器（@ 引用、/ 命令、风格/运镜/特效胶囊）· 参数条「模型 · 16:9 · 2K · 1张」· 摄像机控制 · 预设 · 生成（⌘↵）。

两者都按 §1 的避让规则定位；平移画布时跟随节点，节点完全移出视口时 Composer 停靠在视口底部并显示「定位到节点」。点空白或 Esc 收起。Composer 与工作台（04）是同一组件。

### 4.4 多选

框选 ≥ 2 个节点：选区外框 + 浮动工具条：排列（宫格/水平/垂直）· 保存到资产 · 创建副本（含内部连线）· 打组 / 合并分镜组 · 批量下载 · 添加到 Agent · 创建为 skill · 整组生成。选区右侧 ⊕ 可整体连线。

应用层已提供以下版本化画布命令（`{ type, version: 1, input }`），由同一命令注册表执行；工具条/菜单接线仍属于暂停的视觉工作：

| 命令 | 精确输入与结果 |
|---|---|
| `batch.split` | `input: { batchId: string }`。拆开既有批次，不复制节点或媒体；删除成员的 `batchId/batchIndex/batchTotal/batchPrimary/batchCollapsed` 并令其可见。保留节点 ID、位置、父子归属、媒体与生成来源字段及全部连线；不自动排列，也不强制改变选区。返回 `references.nodeIds` 及 `value: { batchId, nodeIds }`，按原 `batchIndex` 升序、同序号按 ID 排序；缺少序号的成员排最后。批次不存在为 `not_found`。 |
| `storyboard.merge` | `input: { nodeIds: string[], nodeId?: string, displayName?: string, columns?: number }`。2–100 个互异、真实存在且持有耐久图片来源的节点；ID 不得为空或带首尾空白，拒绝未知字段。新 ID 不能已存在；名称去首尾空白后 1–200 字符；列数为 1 到帧数的整数，默认 `ceil(sqrt(N))`，行数为 `ceil(N/columns)`。按传入 `nodeIds` 原序新建一个 `storyboardSplit` 节点，帧 ID 为 `frame-1…N`、`order` 为 0…N−1，不根据画布位置/当前选区重排。 |
| `selection.connect` | `input: { sourceNodeIds: string[], targetNodeId: string }`，1–100 个显式来源汇入一个目标；重复来源按首次出现去重。依次在同一草稿上调用既有连接校验，复用已经存在的精确连线，不造重复边。任一来源缺失、类型/引用不兼容、自连接、环或标签来源冲突均整批拒绝，包含先前在草稿中新建的边。返回 `references: { nodeIds: [...去重来源, targetNodeId], edgeIds }`，边按来源顺序，包含复用边；`creates.edges` 只计新增边。 |

- 分镜合并是复制耐久图片引用，不是栅格拼图、移入组或删除来源。允许持图的上传、图片结果、图片生成、分镜生成、全景节点；无耐久图、临时 `blob:` 等来源拒绝。每帧保留 `imageUrl`、可用的耐久 `previewImageUrl`、画幅和 `sourceNodeId`、`sourceAssetId: '<来源节点ID>:image'`；后者是画布资产目录 ID，不冒充全局资产库 ID。`sourceMetadata` 仅复制已有名称、原文件名、模型、供应商、请求模型、分辨率、宽高和原任务 ID，不补造缺失元数据；匹配实际来源的 `mediaReferences` 同步复制到对应 `frames[i]` 路径。源节点、父组、位置、媒体、配置和所有连线保持不变，新建节点不自动新增来源边。返回新 `references.nodeId`、来源及新节点的 `nodeIds` 和按帧序排列的来源 `assetIds`。
- 三命令均先准备完整图再做一次 CAS 图事务；成功且有变化只增加一条撤销记录，失败或过期审批修订不留部分修改。`selection.connect` 在全部边已存在时成功但不改修订、不新增历史；再次对已拆开的旧批次执行 `batch.split` 是 `not_found`，不是新的复制操作。批次拆分的图撤销恢复完整堆栈与连线，但选区仍遵循画布“实时选择不入撤销”的规则。
- 下载应用层：`collectDownloadableMedia(nodeIds)` 排除收起的次要结果和不可耐久化的媒体；文本节点/文本结果的 `source` 是正文，不作路径或 URL 解析。`prepareAssetDownload({ id, name, kind: 'text', source })` 返回 UTF-8 的 `data:text/plain;charset=utf-8,...` 下载地址，原样保留中文、emoji、空白、换行以及字面的 `asset-media:` / `data:` / `https:` 前缀，不发请求读取这些正文。已有 `.txt/.md/.markdown/.json/.csv/.srt/.vtt` 后缀保留，否则追加 `.txt`；下载后移除临时 `<a>`。

### 4.5 本地媒体编辑运行层

- 统一入口为 `src/features/canvas/application/media/index.ts` 的 `runNodeMediaEdit(nodeId, operation, options?: { signal?: AbortSignal, onProgress?: (fraction: number) => void }): Promise<{ nodeIds: string[], processing }>`；`processMediaEdit(source, operation, options?)` 只解码/转换/编码，不持久化或改图。`node.media.edit` 命令输入为 `{ nodeId, operation }`，取消信号通过注册表执行选项传递，不塞入命令 JSON。进度为 0–1，处理占前 90%，图提交与保存入口调用后到 1。
- 操作判别字段与参数：`image.transform { rotate: 0|90|180|270, flipX?, flipY? }`；`video.captureFrame { timeSeconds }`；`video.trim` / `audio.slice { startSeconds, endSeconds }`；`video.crop { rect: { x, y, width, height } }`（0–1 归一化且完整在画面内）；`video.separateAudio`；`audio.split { atSeconds: number[] }`（严格递增、位于源时长内部）；`audio.rate { rate }`（0.5–2）。时间必须有限，截取满足 `0 ≤ start < end ≤ 源时长`。
- 读取调用时的源节点类型、媒体字符串与项目 ID；不覆盖或删除源媒体。所有输出持久化成功后重新检查源节点仍存在、类型/媒体来源/项目未变，再以当时图修订 CAS 一次提交新结果节点和来源边；全部结果选中、原选区取消、一次撤销，并调用项目保存入口。任一处理/持久化失败、取消、源过期或提交冲突都不产生部分节点/边/历史；处理间发生的其他用户编辑不会被回滚。结果保存 `sourceMediaEdit` 与可用的 `sourceMediaRange`，Agent 来源在异步边界前捕获，只标记本次提交，不把等待期间的手动编辑误归该回合。
- 图片旋转与镜像输出 PNG；90/270° 交换尺寸。音频截取、有序切分和倍速输出 PCM16 WAV；倍速不保调，会同时改变音高。切分以共享采样帧边界连续覆盖原音频。
- 视频按需加载随应用安装的 Mediabunny（MPL-2.0），不依赖系统 FFmpeg。截帧需实际源编码可解码，画面裁剪需源解码器及目标编码器可用。`video.trim` 仅在能够保留请求边界时流拷贝，trim 的边界/时间平移容差均为 0；起点不能精确复制时转码，结束时间落入视频包或音频包内部时对该轨强制转码，不允许为了流拷贝向外保留整个尾包。非对齐裁剪不是“找最近关键帧”或改写时长元数据。音视频分离只重新封装、不重编码，保留未剪辑轨的编码器预卷包，分别输出无声视频和音频。
- `getMediaEditCapability(kind, source?, options?)` 探测本机与实际源的支持情况；不可用返回 `supported: false` 和原因码，不写伪造媒体。此探测不接收具体截取区间，不能预先保证任意边界可流拷贝或可转码，具体操作仍可明确失败。返回 `processing: 'stream-copy' | 're-encode' | 'decoded-pcm' | 'image-transform'`，不得把转码报告成流拷贝。
- SDK 使用当前调用信号与回合信号的组合，经自定义执行器或默认注册表一路传入媒体层，审批恢复也使用当次调用信号。外部 Agent 的停止先 abort 本回合本地执行控制器，再等待原生 CLI 取消确认；本地媒体不得等待该确认才停止。停止只撤销本地工作/未执行审批，不能承诺已提交付费任务被取消或免计费。
- 读取、图像解码/PNG 编码、音频解码/离线渲染、转换初始化与执行均检查取消；不可物理中断的异步 API 由 `waitForMediaTask` 尽早结束调用，迟到的 ImageBitmap 关闭、迟到的转换实例取消，不再持久化或发布结果。取消同时关闭 AudioContext、释放输入/解码/转换资源与临时对象 URL；PNG 回调等迟到值不得启动后续处理。
- 持久化使用既有原生图片/视频保存和 `asset-media:` 存储；音频在桌面与浏览器均可用 IndexedDB 持久化，节点字段不写 `blob:`。取消发生在不可中断的保存期间仍禁止图提交；已完成的内容寻址媒体不删除，避免破坏其他素材对同一内容的引用。以上是应用契约，不代替平台编解码器、原生运行或媒体 UI 的验收证据。

## 5. 连线

- 默认贝塞尔，基础线 2px；悬停/选中显示流光动画（需求 B-12）。
- 悬停连线：剪刀按钮**跟随指针在线上的投影位置**（需求 B-12，比 LibTV 固定中点更顺手），点击剪断；单击连线选中，Delete 删除。
- 连接规则：左入右出；素材节点只能作为上游（需求 C-08）；类型不兼容时目标节点显示禁止态并说明原因。
- 从 ⊕ 拉线到空白松手：弹「用这个节点生成…」菜单（文本/图片/视频/音频/舞台/参考），选择后新节点出现在松手处并自动连好。
- 连线隐藏开关（左下控制条）。

## 9. 撤销

- 所有画布编辑（含整理、Agent 回合、批量导入）进撤销栈；存差量（patch），上限 200 步，持久化最近 50 步。
- 拖拽、缩放尺寸只在松手时入栈；文本编辑按 1 秒停顿合并。

## 10. 实现切分

```
src/features/canvas/
  engine/      视口、输入识别、选择、吸附/参考线、快捷键分层（纯逻辑 + hooks）
  store/       canvasStore（节点/连线/选区）+ history（差量）+ persistence
  nodes/       每种节点一个目录：Node.tsx（外壳内容）、toolbar.ts（动作声明）、schema.ts
  overlays/    NodeToolbar、Composer 挂载、SelectionToolbar、EdgeScissors、placement.ts（避让定位）
  menus/       AddNodeMenu、ContextMenus、CommandPalette
  panels/      AssetDrawer、MaterialLibrary、CharacterLibrary、History、Shortcuts
  tools/       全景/多角度/打光/标注/宫格切分 等编辑器（复用现有实现，拆分迁入）
  migrate/     旧项目迁移
```

`Canvas.tsx` 只做组装（≤ 300 行）。所有画布操作经 `canvasCommands`（与 Agent 工具同源，06 §3）。
