# 大翻新总纲（next 分支）

> 状态：`0.2.0-next.1` 本地预览已构建，进入用户评鉴；用户明确要求先不发布，因此不推送、不合并、不创建 Release。实际实现、验证范围与原始目标的差异以《08-实施与验收》为准，不能把目标当成已完成功能。

## 1. 已拍板的决策

| 决策 | 结论 |
|---|---|
| 重做方式 | 同仓库 `next` 分支：重写前端与渠道层，保留并瘦身 Rust 后端（SQLite 持久化、任务记录、图片处理、HTTP 桥、ComfyUI、外部 Agent 进程） |
| 发版节奏 | 先提供本地评鉴版；按用户最新要求暂停一切发布，评鉴后再决定渠道先行版或整体 0.2.0 的节奏 |
| 主题背景 | 墨染江湖背景暂缓；底座只保留主题插槽（设计 token + z-index 0 背景层），后续 AIGC 定制版只换皮 |
| 技术栈 | React 19、Vite 8、TypeScript 7、Tailwind 4、zustand 5；复用现有 UI primitives 与模型接口，避免为翻新再强制引入第二套组件体系 |
| 画布布局 | 工具左置、底部导航；节点浮动编辑器恒定屏幕尺寸，避边与避让导航，竞品仅作为行为参照 |
| 工作台布局 | 会话列表 + 生成结果流 + 常驻输入框；模型可搜索，参数仅来自渠道声明 |
| Agent | 一个模型无关的运行时，三套工具集：首页 Agent / 画布 Agent / 舞台 Agent（导演台+预演台） |
| 导演台与预演台 | 合并为一个「舞台 Stage」，`mode` 只作能力开关 |

## 1.1 差异化原则

参考 LibTV / 即梦，但不照搬：每个模块规格都必须有「它们的痛点 → 我们的做法」一节。判断标准只有两个：**一眼看懂**、**操作丝滑**（任何操作都有即时反馈、可撤销、不阻塞）。

## 4. 分工

- 主代理：全部前端交互组件、跨模块契约、集成与验收。
- 子代理：调研采集（低成本）、Rust/适配器/迁移/测试（按切片，带契约，不碰 UI）、阶段审查（reviewer）。

## 5. 硬约束

1. **拆分责任**：新增组件遵循单一职责；旧大型模块在接线时渐进抽离，不能为了行数机械切文件或声称已经全拆。
2. **媒体持久化**：工作台与资产库用稳定媒体引用，浏览器二进制进入 IndexedDB；旧画布继续支持原数据与 imagePool，浏览器项目存储已迁到 IndexedDB，不再受 localStorage 约5MB限制。全画布 assetId 化仍须单独迁移验收。
3. **请求体即模板**：渠道请求只发模板里声明的字段（见 02）。
4. **有歧义的提交不自动重试**：可能已被上游受理的请求绝不自动重发，避免重复扣费（#7）。
5. **一条代码路径**：请求预览与真实发送用同一个渲染函数。
6. **撤销覆盖一切画布/舞台编辑**；Agent 的修改同样进撤销栈。
7. **旧数据可迁移**：旧项目、旧渠道配置有迁移器；迁不动的字段显式列给用户，不静默丢弃。
