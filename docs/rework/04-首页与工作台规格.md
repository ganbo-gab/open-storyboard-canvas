## 1. 即梦的痛点 → 我们的做法

| 即梦实测痛点 | 我们的做法 |
|---|---|
| `+` 上传槽直接弹系统文件框，无类型/数量/大小提示 | `+` 弹小菜单：本地上传 / 从资产库 / 从画布节点，菜单底部写明「图片 ≤ N 张 · 视频 ≤ N 个 · 单个 ≤ 30MB」（按当前模型声明）；同时支持拖入与粘贴 |
| `@` 无主体时点了没反应 | 空态面板：「还没有人物 · 从图片创建人物」 |
| `/` 弹窗无搜索，「技能」菜单有搜索，两处能力不一致 | 一个技能面板：`/` 和「技能」按钮打开同一面板，带搜索、最近使用 |
| 11 个模型平铺、无搜索/分组；不兼容只在 hover 才说明 | 模型选择器：搜索 + 按渠道分组 + 最近/收藏；与当前模式/参考素材不兼容的模型**直接显示灰态 + 原因行**，无需 hover |
| 参数条纯文字，「智能比例 / 2K / 2」挤在一个按钮里，热区分不清 | 参数条分段按钮：比例用画幅形状图标、分辨率、数量、时长各自独立可点，点哪段打开聚合面板并定位到对应分组 |
| 输入框不随内容增高 | 自动增高至视口 40%，之后内部滚动；长文可展开为全屏编辑 |
| 9k px 长会话只有「回到底部」 | 右侧细「生成目录」：每批结果一个缩略图刻度，悬停预览、点击跳转 |
| 同一结果的操作散落 4 处 | 结果卡统一操作区：悬停显示 5 个高频（下载 · 用作参考 · 再次生成 · 发送到画布 · 更多）；「更多」与查看器展示全部动作并带文字 |
| 资产页无上传，资产 = 生成历史 | 资产库独立：上传、生成、画布保存三种来源；悬停即可下载/收藏/更多 |
| 画布四个入口，新建另开标签页 | 画布只有一个入口（项目），同窗口打开 |
| 无快捷键面板 | 全局 `?` 快捷键面板，按页面分组 |

即梦值得保留的：同一 Composer 切换多种生成模式只换参数条、比例/分辨率/数量聚合面板、时长「滑块 + 数字」、首尾帧槽位标签写在槽内、结果元信息行「模型 · 时长 · 比例 · 分辨率」、`/ 技能` chip 行、Esc 一致退一层、克制的深色令牌。

## 4. 工作台

布局沿用 video-maker 创作台：左会话栏（268，可收起）+ 中央记录流 + 底部悬浮 Composer。

- **会话栏**：新对话；搜索；置顶；重命名；按项目分组（可选）。
- **记录流**：`column-reverse`，最新在底部贴着 Composer；向上滚动接近顶部预取更早记录；滚动时 Composer 收成胶囊（video-maker 阈值：靠底 120 / 收起 56 / 展开 320），输入中不收起。
- **生成卡**：提示词（@ 引用胶囊可悬停看大图）· 元信息行（模型 · 时长 · 比例 · 分辨率 · 耗时）· 结果网格 · 卡片操作（重新编辑 · 再次生成 · 删除）。生成中显示进度与 0.1s 计时器。
- **结果悬停**：下载 · 用作参考 · 再次生成 · 发送到画布 · 更多（更多 = 全部编辑动作：高清、扩图、局部重绘、多角度、生成视频…，带文字）。
- **生成目录**：记录流右侧 12px 细条，每批一个刻度，悬停显示缩略图，点击跳转。
- **发送到画布**：选择项目（默认最近）→ 作为素材节点落到该画布视口中心；也可把结果直接拖到左侧导航「项目」上投放。

### 4.1 Composer（与画布共用组件）

- 参考区：`+` 菜单（§1）；拖入/粘贴；参考素材按类型独立编号（图1、图2、视1、音1），悬停大图，拖动排序；首尾帧模式下变为两个带内部标签的槽「首帧 / 尾帧」。
- 提示词编辑器：TipTap；`@` 引用素材/人物/文本片段；`/` 技能；风格/运镜/特效以胶囊插入，提交时展开。
- 参数条：模式 · 模型 · 比例（形状图标）· 分辨率 · 数量 · 时长（视频）· 摄像机控制 · 预设；全部由 02 的 `ModelSpec.params` 生成。
- 发送：⌘↵；按钮旁显示「将生成 2 张」；渠道有价格时显示预估。
- 约束就地提示：参考数量超限、时长超范围、提示词超长 → 参数条上直接标红并说明，发送按钮禁用并写原因。

## 5. 查看器

- 全屏遮罩（不切路由）：左大图/视频，←/→ 切换，滚轮缩放、拖动平移；右信息栏：提示词（可复制）、元信息、全部动作（两列带文字按钮）、重新编辑 / 再次生成。
- Esc 关闭；上层浮层（菜单）优先消费 Esc（video-maker 已验证的 `defaultPrevented` 规则）。

## 6. 资产与人物

- **资产**：类型页签（全部 / 图片 / 视频 / 音频 / 文本）· 来源筛选（上传 / 生成 / 画布保存）· 比例 / 分辨率 / 模型筛选 · 搜索 · 按日期分组网格；悬停：下载 · 收藏 · 更多；多选批量（下载 / 删除 / 加标签 / 发送到画布）；拖到画布或 Composer 即引用。页面有「上传」。
- **人物**：名字 + 主图（可多张）+ 音色 + 标签；可从任意图片节点/资产「创建人物」；在 `@` 中优先出现。空态说明人物的用途并给出「从图片创建」。

## 8. 实现边界与当前应用层契约

- 视觉接入方案：从 video-maker 移植 `features/composer/*`、`features/feed/*`、`features/viewer/*`、`features/assets/*`、`components/ui/*`、`styles.css` token 与动效；数据调用应接入下述应用 API，而非另建前端事实源。
- 视觉路由方案：`react-router` 8，页面懒加载，空闲预加载常用页与浮层；不是本节非视觉交付声明。
- 本地数据以当前存储实现为准：原生生成任务沿用 Rust SQLite；会话、资产和库索引使用 §8.1 / §8.3 的 workspace document，不因视觉方案而宣称已新增会话 SQLite 表。

### 8.1 当前工作台应用层契约

- `src/features/workbench/store/workbenchStore.ts` 导出 `useWorkbenchStore`；先调用 `initialize()`，使用 `createConversation/renameConversation/deleteConversation/selectConversation/setDraft` 管理独立会话，`submit` 返回本地任务编号。任务通过 `input` 保留提示词、模型、参数和引用；`results` 为真实生成结果，`failure.kind/message` 为分类失败。
- `WorkbenchConversation.pinnedAt: number | null`、`projectId: string | null` 在新建与旧记录加载时均默认 `null`。`createConversation(title?, projectId?)` 可显式关联项目；`setConversationPinned(id, pinned)` 幂等设置/取消置顶，`associateConversationProject(id, projectId)` 关联或清除项目，两者不改写会话活动时间、不提交生成，变更沿既有会话 document 持久化。`selectWorkbenchConversations(state, {projectId?, text?})` 是纯查询：省略项目返回全部，`null` 只返回未分组会话，字符串精确筛选项目；标题搜索忽略大小写。置顶会话始终在前，分别按 `pinnedAt`、未置顶的 `updatedAt` 倒序，再按 `createdAt` 倒序、id 升序稳定打破平局，不依赖对象遍历顺序。
- 图片/视频使用画布同一 `tauriAiGateway`，文本使用 `submitCustomChatCompletion`，音频使用设置中的已启用音频模型和 `generateAudio`。提交不要求活动画布，不发布画布生成事件，也不创建节点。`importResult(taskId, projectId, resultIndex?, position?)` 才显式向指定项目添加素材节点；`position` 为 flow 坐标，缺省落在目标视口中心。活动项目走原批量节点/历史路径并选中新节点，未打开项目沿用项目记录和 imagePool 编解码，不切换当前项目；两条路径均等持久化后返回节点 id。
- `poll/resume/recoverResult` 仅查询既有任务或取回既有结果，绝不再次提交；`cancelWaiting` 只暂停本地等待，不声称取消上游计费任务。没有任务编号的中断提交恢复为 `unknown`，不能伪装成安全重试。
- `regenerate(taskId)` 是用户明确发起的全新付费提交，沿用原输入和原会话，不修改或重试原任务。`deleteTask(taskId)` 只移除任务和其消息并保存历史，资产引用/文件不受影响；尚未确定结束的 `queued/submitting/running/materializing/unknown/recoverable_wait` 均拒绝删除（`workbench.taskActive`），包括已暂停本地等待的任务。UI 通过 `canDeleteWorkbenchTask` 判断操作可用性；跨会话任务抽屉使用 `selectActiveTasks`（按创建时间倒序）及 `selectActiveTaskCount/selectActiveTaskCounts`。
- `workbench/application/workbenchValidation.ts` 的纯 `validateWorkbenchDraft(draft, context)` 返回 `{issues, blocking}`；`getWorkbenchValidationContext(draft)` 从原生渠道的当前模式、参数/槽位及 legacy catalog 的明确声明构建上下文，不把 picker 的兜底值当约束。`describeReferenceLimits(draft, context?)` 只返回已知数量/字节上限。提交复用同一校验，失败抛出带相同 `issues/code` 的 `WorkbenchDraftValidationError`，不会创建任务或发送请求。渠道未声明的提示词、数量、时长/素材字节限制不臆造。
- 会话和资产索引使用带版本、结构校验和事务提交确认的 IndexedDB `storyboard-copilot:workspace`（`documents` / `media`）；首次读取自动迁移旧 localStorage 会话与资产索引，旧值保留不覆盖。浏览器 data/blob 素材在持久记录前转存二进制 Blob，索引只保存 `asset-media:<id>`，避免已满的项目 localStorage 挤占工作台。桌面图片/视频复用原媒体文件持久化命令，生成任务仍使用既有原生任务 SQLite；目前没有新增会话 SQLite 表。清理站点/WebView 数据会删除本地索引与浏览器素材。浏览器上游任务刷新后恢复能力仍以原网关为准；文本/音频无持久上游任务编号，中断不自动重发。
- 渲染素材应异步调用 `getAssetDisplaySource(source)`，把稳定引用解析成当前会话可用的 blob URL；渠道请求和旧画布导入边界使用 `getAssetPortableSource(source)` 临时取字节，不将 blob URL 写回持久索引。`initialize()` 等待索引迁移/加载；`submit()` 等待参考素材与本地任务事务提交完成才发送付费请求。IndexedDB 真实故障公开 `storageStatus.mode = memory` 并阻止新付费提交，损坏或未来版本原数据不覆盖；浏览器磁盘存储仍受站点配额与系统空间限制。
- `src/features/assets/application/assetCatalog.ts` 的 `listAssets/resolveAsset` 聚合所有项目生成、上传和画布素材及工作台保存结果；`saveAsset/renameAsset/favoriteAsset/deleteAssetReference` 只维护资产引用/覆盖层，删除操作不删除用户文件或画布节点。`assetMetadata.ts` 的 `normalizeAssetMetadata` 是存储、查询与导入共同边界：合并既有 `assetMetadata`，保留完整 `config`、`references`、提示词与其他 provenance，统一 `resolution/aspectRatio/model/jobId/durationSeconds`，只接受已知的正整数 `width/height`，不由「1K」等标签猜像素尺寸；`generationDebugContext` 不入索引。
- `filterAssets` 支持类型、来源（查询上传使用 `upload`，记录为 `uploaded`）、比例、模型、`resolution/width/height`、文本、收藏和闭区间时间；尺寸筛选使用上述规范化事实。`groupAssetsByDate(assets, now)` 按本地日历日期倒序输出 `key/date/period/assets`，`period` 为 `today/yesterday/earlier`。`tagAssets` 合并去重标签并等待覆盖层事务提交；`deleteAssetReferences` 批量只删除引用。`importAssetToProject(assetId, projectId, position?)` 与工作台导入共享逐项目串行、无生成/无切项目、持久化完成后返回新节点 id 的路径；节点保留 `assetMetadata/assetOrigin/assetId/workbenchTaskId`，连同完整参数、素材引用和来源一并跨项目保存。
- `assetFiles.ts` 的 `assetFileKind(file)` / `importAssetFile(file)` 为选择、拖入等调用方提供同一类型化文件边界：只接受明确的图片、视频、音频 MIME 或文本 MIME；仅无 MIME / `application/octet-stream` 时可按已知文本扩展名识别文本，未知二进制返回不支持，不伪装成剧本或图片。图片（含 PNG）先解码读取真实宽高；视频读取 metadata 的真实宽高及可得时长，写入约分后的比例、`宽x高` 分辨率以及 `originalFileName/mime/size`，不凭文件名或预览猜尺寸。
- `downloadSourcesFor(ids)` 返回原始源和素材 `kind`，不是预览图、不自行写文件；`assetDownloads.ts` 的 `prepareAssetDownload/downloadAsset/downloadAssets` 执行下载边界。文本 `source` 始终是字面内容，以 UTF-8 `text/plain` 编码下载，保留 Unicode、空白及 `https:`、`data:`、`asset-media:` 等字面前缀，不将它当链接、路径或媒体引用解引用；非文本才解析稳定媒体引用。


### 8.2 知识库核心契约（L-01～L-04）

- `src/features/knowledge` 统一导出领域、应用服务及 `useKnowledgeStore`。笔记唯一事实源为用户明确选择的文件夹中的标准 `.md`，附件在 `attachments/`；设置只保存 `knowledgeVaultPath: string | null`，默认 `null`。root 必须是显式绝对路径，不展开 `~`、环境变量或默认文档目录；未设置时 store 为 `status = unset`，`getService()` 抛 `VAULT_UNSET`，调用方应进入选择/设置流程，不静默创建默认 vault。
- `KnowledgeVaultIO` 必须实现独立的 `openVault(root)` 与 `initVault(root)`，不能以可选方法或相互回退混淆授权。`initialize()` / `initialize(undefined)` 只读取已保存授权，调用 `openVault`；原生 `knowledge_open_vault(root)` 要求已有、无别名替换的授权 root，并原样返回同一 root，不 canonicalize、不建目录（包括 `attachments/`）、不改写保存的授权。缺失目录、root 或任一祖先变成符号链接/不安全别名时直接失败，不能跟随到新位置。只有 `chooseVault()` 的显式选择或 `initialize(absolutePath)` 才调用 `initVault` / `knowledge_init_vault`，允许创建不存在的路径并在这次明确授权时解析所选别名，成功加载后保存返回 root。`initialize(null)` 持久清除授权并回到 `unset`；取消选择器不清除原授权。`ensureKnowledgeService` 对并发 Agent 调用共享初始化，自动重开时必须省略 root 参数，不能把已保存路径重新传成显式授权。
- Rust `knowledge_*` 命令负责目录树、批量读取、原子临时文件写入、移动与 wikilink 重写；`.obsidian/` 从不写入，目录、搜索与索引排除 `.trash/`、`.obsidian/` 和内部 `.knowledge-*` 临时项。相对路径按字面文件名处理，不 URI 解码：拒绝绝对路径、遍历、空段、尾部点/空格、保留目录与任何 `%HH` 十六进制编码片段（含 `%25`），但 `100% reference.png` 这种普通百分号名称允许；不做多轮解码猜测。
- 附件应用 API 为 `listAttachments(folder?)`、`importAttachment({name, bytes, folder?})`、`readAttachment(path)`、`removeAttachment(path)`，对应 `knowledge_write_attachment/read_attachment/remove_attachment` 及目录树读取。只接受 `attachments/` 下的非 Markdown 文件；`name` 仅文件名，嵌套目录用相对 `folder`。字节类型为 `Uint8Array`，允许空文件和未知二进制，单附件上限 `MAX_KNOWLEDGE_ATTACHMENT_BYTES = 512 MiB`；读写两端检查上限，原生读取通过二进制 IPC 返回，非 JSON 字节数组。附件 MIME 仅扩展名派生的下载元信息，不声称验证内容或允许执行。导入可创建缺失的嵌套目录，按 `name 2` 避重并使用 create-only 原子发布，竞争冲突继续避重，绝不覆盖旧附件。
- `trash(path)` / `removeAttachment(path)` 移入 vault 内 `.trash/`，不是系统回收站、不永久删除；返回的是实际回收条目相对路径 receipt（不带 `.trash/` 前缀，碰撞后可能变名）。`listTrash()` / `refreshTrash()` 列出回收条目，`restore(receipt, destination?)` 缺省恢复到 receipt 同名相对路径，若需原名应显式传 `destination`。恢复拒绝覆盖已有目标；笔记仍须为 `.md` 且不得恢复进附件区，附件须留在 `attachments/` 且不得改成 Markdown，目录不得跨越附件/笔记边界。
- 原生附件读写/移入回收站与通用恢复使用受约束的文件系统提交。Unix 从根及每级祖先以 no-follow 目录描述符打开；附件临时写入后同步并原子发布，create-only 使用不覆盖提交；macOS / Linux 的回收与恢复使用各自原子 no-replace rename，未支持的原子移动平台 fail closed。Windows 路径从盘符到 vault 的祖先由目录列表访问权限与禁止写入/删除共享的句柄固定，拒绝 reparse point、junction、云占位及 8.3 短名别名，按句柄报告的 normalized long name 校验组件；仅支持可提供所需句柄操作的本地 drive-rooted NTFS/ReFS，不支持的命名空间/文件系统失败关闭，不退回不安全 pathname 操作。此为实现边界，不代表 Windows 运行时验收完成；跨目标编译也不等价于实际 Windows 文件系统/竞争测试。
- Markdown 使用 `yaml` 文档模型，保留未知 frontmatter 键；无修改时完整往返保留原字节，打标时保留正文原字节。索引含标题、别名、正文、frontmatter/行内标签及 wikilink 反链；使用内存索引而非第二个可漂移数据库。初始化一次批量 IPC 读取，后续按 mtime+size 增量重读，匹配标题优先于标签、正文并返回上下文片段；5,000 篇规模功能覆盖不等于 UI 帧率证据。
- `refresh(force?)` 为 single-flight 刷新；刷新中发生变更或强制刷新请求会追加扫描屏障，变更方法等到包含自身写入的扫描完成后才返回，不把旧扫描当新索引。`startPolling(3000)` 返回清理函数并串行轮询外部变更。切换/清除 vault 后，旧 vault 的初始化、刷新、打开笔记、附件/收录/整理结果、错误与轮询回调均不得发布到当前 store；打开笔记另以请求序号避免慢响应覆盖更新选择。编辑器仍须独立保留 dirty 草稿，外部更新 `activeNote` 时提示冲突，不丢弃未保存输入。
- `ingest` 接收文本、URL、文件字节或 `CanvasNodeSnapshot`（kind/title/prompt/params/media 引用），写入带 created/source 的笔记。URL 只保存原链接与主机名标题，不网络抓取；画布媒体由注入的 `KnowledgeMediaResolver` 读字节，默认适配器只读已有本地/asset-media/data/blob 素材，远程媒体需先下载。附件和笔记均按 `name 2` 自动避重并通过 create-only 创建。
- AI 整理不内置模型调用：向 `organize(kind, paths, model)` 注入 `(KnowledgeModelRequest) => Promise<string>`。严格 JSON schema 校验 classify/tag/moc/summary，拒绝未知字段、越界路径、未选中笔记和重复目标；模型调用期间正文变化则拒绝陈旧结果。应用层先完成正文编辑再移动，避免旧正文覆盖 wikilink 重写。`createKnowledgeAgentTools(serviceOrGetter, model?)` 导出 `kb_search/read/write/organize` 的 zod、JSON schema 与经解析 handler，不自行注册 Agent；接入方必须将 `mutates: true` 工具接入既有审批链，附件二进制不暴露给这些 Agent 工具。

### 8.3 素材、工具箱与生成历史核心契约

- `src/features/library` 导出三个非 UI 数据核心。`useMaterialLibraryStore`、`useToolboxStore`、`useGenerationHistoryStore` 使用既有 workspace document / IndexedDB 约定，挂载面板先调用 `initialize()`，并呈现 `storageStatus`；均未新增依赖或复制媒体文件。
- 素材库提供风格、特效与十二种运镜的可编辑内置正文，支持 CRUD、上架、全量排序、内置恢复和版本化 JSON 导入导出。提示词预设、收藏和功能模板仅通过适配器投影既有 `settingsStore` / `promptLibraryStore` 的正文，库中只保存其上架、标签、预览、顺序元数据；既有调用者仍读同一份正文。功能模板标题可按其 source id 查现有 `PROMPT_TEMPLATE_DEFINITIONS.titleKey` 翻译。上架只决定素材库可选项；调用方通过 enabled 筛选，不改变旧设置中预设的存在性。`applyMaterialToPrompt` 使用空行拼接正文，禁用素材不应用。
- 工具箱 `saveGroupAsTemplate` 只保存指定容器及递归子节点、内部连线，媒体转为既有稳定引用。`instantiateTemplate` 复用画布复制工具一次性重映射节点、父组、内部边及结果引用，并清除生成运行状态；`applyTemplateToCanvas` 走与内部粘贴相同的 revision 检查图事务，整次添加可一步撤销。`executionOrder` 先对组内完整依赖图拓扑排序，再返回启用的生成节点；环路抛出带 nodeIds 的 `ToolboxError(code='cycle')`，不付费执行。
- 历史中的工作台记录直接投影已持久化 tasks；画布在共享提交入口记录不可变输入快照，完成状态及全部结果由结果节点投影追加到只增日志。Agent 发起的画布/首页任务标记 surface=agent。`query` 支持来源、模型、状态、闭区间时间、项目与全文筛选；`jumpToHistorySource` 只返回导航描述，不擅自切项目。`reuseParams` 返回工作台 draft 或画布节点草稿（含 tool/count），不自动提交；画布恢复原始 draft，而非重复叠加摄像机/预设的编译提示词。`refreshGenerationHistory` 仅查询已有原生任务，适用于未打开来源画布的状态刷新；没有保存过提示词的历史原生任务不会伪造缺失参数。
- 本节为应用层契约，不代表面板、拖拽、Composer 胶囊或真实供应商验收已完成；这些 UI 由主线程单独接入。

### 8.4 Agent 全局默认值（应用层）

- `settingsStore.agentDefaults` 由 `agentDefaultSettingsSchema` 严格校验，形状为 `{ modelId: string | null, executionMode: 'manual' | 'auto' }`，默认 `{ modelId: null, executionMode: 'manual' }`；设置迁移/加载会规范化旧值，损坏模式不得将用户升级为自动执行。`setAgentDefaults(patch)` 只更新此配置，不改写已有会话。
- `resolveAgentDefaults(overrides?)` 仅为缺省字段补全全局值；显式 `modelId: null` 保留「未选择」，不等同缺省。`runCanvasAgentTurn` 的优先级为本次显式模型/模式 → 已加载 session 的 `modelRef/executionMode` → 全局默认；选中的模型不可用时明确要求重新选择，不静默切换其他渠道。新会话继承最新全局值，继续已有会话保留其选择；该 API 不表示设置页或 Agent 模型选择 UI 已完成视觉验收。
