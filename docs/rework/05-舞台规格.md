# 05 · 舞台规格（导演台 + 预演台）

> 导演台＝静态摆拍出分镜图；预演台＝在同一场景上加时间维度出白模预演视频。合并为一个「舞台 Stage」。`workspace: 'director' | 'previs'` 只决定面板和播放能力；持久化的 `BlueprintNodeData.mode: 'flat' | 'panorama'` 保持原义，不能混用。

> 状态边界：用户最新已暂停前端与本会话 Opus 调度；§2–4 的布局、控件、手势与视觉反馈仍为未全部验收的目标，已写代码不回滚。§6–7、§9 的应用命令与截图桥已有独立集成契约，不代表对应控件或视觉/原生 GPU 性能通过。

## 2. 我们的差异点（不照搬）

1. **不阻塞**：读图/文字建场景在后台进行，期间可以照常加人物、机位、画轨迹；场景结果到达后作为一个可撤销的「场景替换」操作合入，人物位置保持。
2. **看着画面调**：所有机位参数旁都有实时画中画；拖滑杆即看到构图变化。
3. **一个变换手势体系**：G 移动 / R 旋转 / T 缩放 + 拖轴变黄 + 直接拖对象贴地滑动；与画布共用 Esc / ⌘Z / 空格 语义。
4. **零门槛上手**：首次进入给 3 步引导条（放人物 → 画路线 → 播放），可关闭；每个按钮悬停 600ms 显示名称 + 快捷键 + 一句用途。
5. **一键回画布**：截图、四视角截图、预演视频都直接作为下游节点落到画布，并自动连线。

## 4. 交互

### 4.1 选择

| 操作 | 反馈 |
|---|---|
| 掠过对象 | 脚下细 hover 环 + 名牌提亮；射线未命中时取屏幕 24px 内最近对象（薄道具也能点中） |
| 单击 | 选中：主题色环 + 描边；检查器切到该对象；时间轴对应轨道高亮 |
| Shift/⌘ + 单击 | 加选/减选；gizmo 挂在选区几何中心 |
| 空地拖拽 | 框选；顶部浮出「已选 N 个 · 隐藏 · 锁定 · 删除」 |
| 双击对象 / F | 视角飞到该对象；当前选中是机位时设为其看向目标 |
| Esc / 单击空白 | 清空选区 |

时间轴点轨道名 = 选中场景对象，两边共享同一份选区状态；锁定/隐藏对象仅能从对象列表新选中，以上仍为视觉交互规格。已提供的应用层边界如下，不另建持久化选区 store：

- `resolveStageSelection(items, currentItemIds, { itemIds, mode, source })` 返回 `{ itemIds: string[], primaryItemId: string | null }`；`mode: 'replace' | 'add' | 'toggle' | 'remove'`，`source: 'viewport' | 'timeline' | 'outliner'`。每次请求最多 100 个 ID，按首次出现去重；请求不存在的对象报错，旧选区中已删除的 ID 则清理。viewport/timeline 不能新选中 `hidden === true` 或 `locked === true` 的对象，outliner 可以；remove 允许移出这些对象。主项为结果选区最后一项，空选区为 null；调用者维护这份瞬态值，选择本身不写图、不入撤销。
- `stageCommands.executeSelection(nodeId, itemIds, operation, expectedRevision?)` 接受 1–100 个目标（去重后保持顺序），`operation` 为 `{ type: 'update', patch }` 或 `{ type: 'remove' }`；patch 使用 `stageItemSchema` 去掉 id 后的严格部分字段。内部生成整批 `object.update/remove`，同一修订校验、一次提交、一步撤销；任一缺失/锁定/非法目标让整批失败。返回舞台变更结果及 `selection`：更新保留目标并以最后一项为主项，删除返回空选区。
- `patch: { hidden: true|false }` 和 `{ locked: true|false }` 复用此入口，不是新的 UI。已锁定对象只接受单独的精确解锁补丁 `{ locked: false }`；解锁夹带位置、隐藏等其他字段仍拒绝。对象删除、人物姿势/动作、对象轨迹与关键帧，以及被该对象动作轨直接/嵌套引用的共享片段编辑也受锁保护。需要解锁后再编辑时，明确发送两条有序命令，可用 `execute([...])` 在同一事务内准备；不得以批量操作绕锁。隐藏仅是可见性/选择标记，不替代编辑锁。

### 4.2 变换

- G / R / T 切换现有 Three.js `TransformControls`；悬停或拖动的轴变黄，其他轴变暗。不以切换渲染框架作为交互改造前置条件。
- 拖动中轴旁显示 `Δ 1.25m` / `Δ 15°`；按住 ⌘ 吸附 0.5m / 15°；拖动期间自动禁用视角控制。
- 人物与物体默认贴地（Y 锁定，Shift 临时解锁）；机位允许 Y。人物旋转默认只给 Y 环，Shift+R 解锁三轴。
- 不进 gizmo 时直接按住对象拖 = 地面滑动，0.5m 吸附。
- 松手才写入撤销栈：一次拖拽 = 一条历史（「移动 人物 1」）。

### 4.3 机位看向（显式三态）

应用命令的 `lookAt: { mode: 'target', targetId, bodyPart? } | { mode: 'point', point } | { mode: 'free', rotation }` 映射到现有摄影机关键帧：target 写 `trackTargetId`，point 清除跟踪并写 `target`，free 清除跟踪并写 `freeRotation`（XYZ 欧拉角，弧度）及前向目标。求值和渲染均以显式 free 旋转优先，包含 roll；旧关键帧无此可选字段时保持原行为。

- 检查器「看向」下拉选对象 → target；机位与目标间画细虚线。
- 拖机位前方的视线端点小球 → point。
- 用 R 旋转机位 → free。旋转数值只在 free 下生效，界面明示当前态。

### 4.4 轨迹（三种画法，人物与机位共用）

| 画法 | 操作 | 反馈 |
|---|---|---|
| 自由画 | 按住左键在地面画 | 实时笔迹；松手 Douglas-Peucker 简化到 ≤ 20 点 |
| 逐点 | 依次点击，Enter/双击结束 | 点编号；末点到光标虚线；提示条「已 4 点 · 回车结束 · Esc 取消」 |
| 直线 | 点起点、点终点（Shift 正交） | 实时长度「6.4m」 |

画完自动在该对象轨道插入路径片段（人物默认带「走」动作）并展开空间轨迹子轨；轨迹旁浮出时长胶囊「4.8s」，拖动即改时长。单击已有轨迹进入编辑：拖点、中段双击插点、Delete 删点、起点旁小环切闭合。机位轨迹的点带高度。

### 4.5 时间轴

- 拖片段：平移，吸附 0.1s / 相邻边界 / 播放头；拖动时显示 `2.4s → 5.9s`。
- 拖边缘：改时长（≥ 0.2s）；路径片段改时长 = 改速度，步频联动。
- ⌘ + 拖复制；S 在播放头分割；Delete 删除；片段可置顶（重叠时优先求值）。
- 空格播放/暂停；←/→ 单帧（24fps），Shift 10 帧；拖刻度尺擦洗。
- 轨道名右侧 `+`：动作卡网格（悬停显示姿态缩略图）、「相对位置跟随」「新建特写跟踪」。
- 特写跟踪参数：距离、高度、水平角、俯仰、焦距、阻尼、锁水平；拖任一参数画中画实时变化。
- 总时长缩短到小于末尾内容时提示，不静默截断。应用层为 `{ type: 'playback.update', duration: number, loop?: boolean }`，duration 必填且为 0.5–120 秒；检查摄影机关键帧/机位区间末尾、对象关键帧、动作关键帧，以及已放置片段在相位偏移与后续中断之后的实际占用末尾。未被后续动作中断的循环片段占用到原总时长；若新时长覆盖不了任一有效内容则整事务拒绝，不截片段、不裁关键帧或自动改动作相位；未放置的动作库片段不独占时间轴。

### 4.6 关键帧

- K（兼容 I）在播放头为选中对象插关键帧，记录位置/旋转/焦距（机位）。
- 拖菱形改时间（吸附 0.1s）；Delete 删除；右键选缓动 `linear / ease-in-out（默认）/ hold`。
- 框选多个关键帧后可统一设置看向（覆盖 LibTV「定点跟拍」「轨迹跟拍」流程）。
- 应用命令统一接收场景绝对秒。V1 `customClips[].keyframes[].time` 仍保存片段局部秒；编辑/分割必须显式传 `clipStart`，转换为 `absoluteTime - clipStart`，避免重复减偏移。旧 `cameraTrack`、`objectTracks`、`actionTracks` 保持绝对秒。

## 5. 读图 / 文字建场景

1. 用户上传 1–3 张参考图或输入描述（任意文件名；超长名在本地重命名）。
2. 舞台应用服务调用用户显式选择的已配置聊天 `modelId`，不自动选择第一个可能计费的模型；有参考图时必须支持视觉。输入引用当前画布或全局资产库的图片 `assetId`，仅服务内部解析图片；输出只允许已有可渲染预设、位置、旋转、缩放、人物动作和建议摄影机，不声称完成真实空间重建或生成新几何。
3. `draftScene` 返回严格 schema 校验后的草案，不修改场景。用户点「采用」后才调用 `applyDraft`（一条撤销记录），可只采用物体、人物或摄影机。当前采用方式是添加到现有场景，保留已编辑人物的位置；预览层由舞台 UI 消费草案实现。
4. 可选：参考图生成全景背景（现有全景能力）作为环境球。
5. `draftScene(request, signal?)` 后台进行，不阻塞其他编辑；发起请求前和响应后检查取消信号，停止后不返回过期草案。当前聊天网关未提供物理网络中断，取消不能承诺已提交请求免计费。
6. 图像草案提示先估计地平线/消失方向，再估计相机高度、俯仰与垂直 FOV，并用目录中人物/门/车辆的已登记米制高度锚定比例。图像响应必须带 `estimation.uncertainty`；可观察时填写 `cameraHeightM`、`horizonNormalized`（画面顶部 0、底部 1）与 `scaleReference`，不可观察时省略数值、说明歧义。草案严格检查预设类别、真实动作 id 及相机高度与估计值的一致性；仍只调用显式选择的真实已配置视觉模型，不做伪重建或付费自动重试。

## 6. 当前数据契约（保持 V1）

舞台命令直接读写画布中的 `BlueprintNodeData`，不另建一份不兼容的 StageDoc 或第二个持久化 store：

```ts
interface StageSnapshot {
  nodeId: string;
  revision: number;
  data: BlueprintNodeData;
}
// data.items: 原有 BlueprintItem（保留 x/y 与可选 pos3d）
// data.motionProject?: DirectorMotionProjectV1
// V1: cameraTrack、objectTracks、actionTracks、customClips
```

- V1 只有一条成片摄影机轨道；不把摄影机伪装成不能被现有网格工厂渲染的普通物体。
- `BlueprintItem.hidden?: boolean`、`locked?: boolean` 是原 V1 对象上的可选字段，不升级文档版本；旧文档省略时仍可见、可编辑。持久化读取对损坏/非布尔旧值按未设置处理，不把 `"true"` 等真值字符串解释为启用；应用命令 schema 则严格要求布尔值并拒绝未知字段。标记修改与其他对象属性同属原图历史。
- 三种画法共享现有距离定速路径关键帧。自由画保留端点和主要弯折，最多 20 点；路径写入指定绝对时间区间，区间外关键帧保留，人物区间默认走路动作。
- `customClips` 是原有动作库片段，不假称独立的空间路径片段。`{ type: 'clip.split', clipId, time, clipStart }` 的 time/clipStart 均为场景绝对秒，仅一次转换为 `localTime = time - clipStart`；左右片段各至少 0.5 秒。左片段保留原 ID，右片段及新边界/右侧帧获得独立 ID，右侧时间以 0 起算；跨分割点的 smooth 曲线保留原 `easingRange` 子区间。程序动作/嵌套片段边界通过 `actionOffsetSeconds` 延续相位，不把采样出的活动关节固化为静态姿势，也不重启动作。
- 分割同步改写实际动作轨与其他库片段中的引用：已有相位落在右段者改指向右 ID 并减去分割偏移；仍在左段者仅在到达分割点且未被下一关键帧中断时添加右段放置帧，保留之后更晚的动作权威性。已放置或被其他片段引用的循环片段需先显式取消循环再分割；失败/过期修订不产生半个片段或部分引用更新，一步撤销恢复原片段、边界和所有引用。
- 旧静态文档没有 `motionProject` 也能直接编辑；未涉及的背景、参考图、机位参数、自定义姿势与已保存工程快照不替换、不清空。撤销恢复整个原始节点。
- 独立 trajectory/clip V2 结构不是本次落地前提；未来采用时必须另有完整迁移、渲染与夹具验收，不在读取 V1 时猜测转换。

## 7. 已落地应用边界与集成

- 保留当前命令式 Three.js 渲染器、网格工厂、播放和录制；不要求引入 `@react-three/fiber` 或 drei。
- `src/features/stage/application/stageCommands.ts` 导出 `stageCommands`：`query/create/open/execute/executeSelection/direct/draftScene/applyDraft/capture/captureFourViews/record/undo/redo`；应用调用者与舞台 Agent 复用该服务，视觉控件接线状态不由此列表推定。
- `execute(nodeId, command | command[], expectedRevision?)` 先严格校验、在内存准备，再通过 `canvasStore.commitGraphTransaction` 一次提交。批量失败不产生部分修改；一次成功批量只有一条撤销记录。模型调用与截图、录制等外部副作用不混入图事务。
- 参数 schema 从 `stage/domain/stageSchemas.ts` 导出，拒绝未知字段、悬空对象/片段引用、递归动作片段和越界时间；缩短总时长不能静默裁掉关键帧。
- 播放/录制继续共用 `sampleNormalizedDirectorMotion`，不按帧写 Zustand。录制继续走现有 `director.record` 的真实导出路径。
- 截图桥通过 `registerStageViewport(nodeId, bridge)` 注册，返回卸载清理函数。准确签名为 `bridge.capture(signal?: AbortSignal): Promise<{assetId:string}>`、可选 `captureAt(timeSeconds:number, signal?:AbortSignal): Promise<{assetId:string}>`、可选 `captureFourViews(timeSeconds?:number, signal?:AbortSignal): Promise<Array<{assetId:string,view:'front'|'right'|'back'|'left'}>>` 和可选 `setWorkspace(workspace:'director'|'previs'): void`。`stageCommands.capture(nodeId,timeSeconds?,signal?)` 返回 `{nodeId,assetId,timeSeconds?}`；`stageCommands.captureFourViews(nodeId,timeSeconds?,signal?)` 返回 `{nodeId,images,timeSeconds?}`。指定时间必须有限且在当前时间轴的 `[0,durationSeconds]` 内；没有 motionProject 时只能指定 0。
- `capture` 省略时间读取真实当前挂载视角；指定时间必须调用 `captureAt`，在该绝对时刻使用统一运动求值器及成片摄影机，缺成片机位明确失败，不退回当前帧。四视图按 `front/right/back/left` 固定顺序返回四个互异资产；相机分别沿世界 +Z/+X/−Z/−X 看向同一采样场景包围盒中心。一次四视图冻结同一个时间/场景快照，指定时间精确采样，不指定时也只读取一次当前播放时间，不能边播放边各取不同帧。
- 真实截图路径使用独立场景与相机克隆做离屏渲染，排除网格、选中/hover 环、gizmo、运动路径及姿态编辑辅助物；不暂停/seek 实时播放，不改播放头、实时相机、orbit/pilot、人物姿态或导出状态。`renderStageOffscreenImage` 使用独立 render target，在线性 HDR 场景输出后经 Three.js `OutputPass` 恰好一次完成显示色彩/色调转换，再像素读回并翻转 Y 编码 PNG；不抓取屏幕 DOM 或复用缓存截图。输出尺寸遵从截图配置并检查 GPU texture 上限，保持实时 canvas 尺寸不变；临时 target/pass 与仅由本次创建的网格/灯光阴影资源释放，借用的原几何/材质/纹理不得销毁。
- 同步边界不是固定延时或“下一帧应该好了”：shell 只能引用已提交输入，且这些输入须与 Store 当前场景/运动/相机/光照/画幅/输出尺寸保持对应；渲染器在所有网格、环境与摄影机同步 effect 完成后才发布该代 `BlueprintSceneCaptureRevision` 确认令牌，新 commit/卸载先撤销旧令牌。采样快照绑定该令牌；待同步、模型/全景未就绪、场景在捕获中改变，或 PNG 异步编码完成时令牌已变化，都明确拒绝旧像素，不用新修订号给旧 renderer 贴标签，也不任意延时重试。调用者应等真实同步完成后显式发起新捕获。
- 单个舞台的捕获所有权覆盖渲染、不可取消的收尾与持久化；重入请求明确报 busy，不排队套用旧快照。外部 signal、视口卸载或重新注册会取消本代捕获；新注册不能与旧捕获尚未结束的清理竞争。通用 `createStageCaptureBridge` 也支持需临时修改现场的 adapter，但此类 adapter 必须成对提供 suspend/不可取消 restore，等待在途 render 完成后再恢复；当前离屏 adapter 不修改现场，因此不需要暂停/恢复实时状态。
- 全部图像渲染完成后才逐一持久化到真实媒体与全局资产目录；每张必须为非空图片且返回可解析稳定 `assetId`，服务兼容旧画布图片目录 ID，但不强制新增节点或关闭舞台。取消/渲染/保存失败时清理本批已登记资产引用，不发布部分四视图；清理失败显式带回原错误与清理错误，不伪称成功。底层已完成的共享内容寻址媒体不作破坏性删除。未打开视口、缺精确时间/四视图桥或图形上下文丢失均明确报错，不能拿旧图、当前帧或模拟图代替。
- `stageCommands.test.ts` 覆盖批量/撤销、旧文档保留、绝对/局部时间、分割 ID/插值/动作相位、机位旋转优先级和草案校验。UI、性能与录制验收仍按下节执行，不能用单测代替浏览器操作证据。

## 9. 确定性故事导演

- `application/storyPlan.ts` 导出 `storyPlanSchema`、`stageDirectInputSchema` 及 `StoryPlan/StoryPosition/StoryShot`。所有对象严格拒绝未知字段；总时长 0.5–120 秒。`cast` 显式区分 `{kind:"existing",itemId}` 与 `{kind:"new",itemId,presetId,label,heightM,position?}`；新人物必须使用真实人物预设，按登记高度缩放。`setObjects` 只接受非人物目录预设，可添加或按 itemId 更新已有布景。
- `beats[]` 指定 `start/duration/blocking[]`。每位演员可给 `from/to`、`travelSpeedMps`、真实 `actionId/poseId`、`facing/lookAt`。位置为 `{x,y,z}`、`{actorId,offset?}` 或 `{markId,offset?}`；marks 为计划内命名位置。相对演员终点在节拍开始时解析，不依赖 blocking 数组顺序。facing 为弧度或位置引用；lookAt 在节拍中采样，演员引用瞄准头部，超出真实关节范围时返回警告。
- `shots[]` 指定 `start/duration/subjectItemIds/size/angle/movement/transition`，可选 `fov/azimuth/blendSeconds`。景别：`extreme-wide/wide/full/medium/close/extreme-close`；角度：`eye/high/low/overhead`；运动：`static/push/pull/pan/orbit/track/crane`；转场：`cut/blend`。blendSeconds 必须小于镜头时长。
- `compileStoryPlan(plan,snapshot)` 返回 `{commands,warnings,durationSeconds,captureTimes}`，不修改 store，不调用模型。演员与摄影机重叠区间、无效目录 id、悬空演员/mark/镜头主体、越界时间均拒绝；相邻区间可共享边界。自然移动时长为距离 / 目录 locomotion 速度（默认 walk 1.35m/s），早到后保持终点直至后续 blocking；节拍不足或 0.2s 最小时长约束会显式返回实际速度/时长警告，不移动其他节拍时间。
- `computeStoryFraming` 在相机空间投影主体包围盒各角点，根据登记米制高度、主体跨度、景别裁切、画幅与垂直 FOV 求距离。高/低/顶角均参与拟合；宽深为保守近似而非几何扫描结果，每镜头明确返回 estimated-bounds 警告。必须通过真实截图检查姿态、遮挡及实际物体几何。
- hard cut 在入镜边界使用 `hold`，上一运动镜头保留边界前 1µs 的末态，避免把上一镜头的整段运动冻住或插值为滑镜。blend 在明确的入镜时间段内插值；外部摄影机关键帧保留。
- `stageCommands.direct(nodeId,plan,{dryRun,expectedRevision?})` 预览和执行共用同一编译器；dryRun 返回修订和完整命令，不写历史。执行一次准备、一次图事务提交，超过 100 条的编译结果也不分批提交；任一步失败全部回滚，一步撤销完整故事。低层 `execute` 仍保持 1–100 条限制。
- 低层补充：`person.pose` 可传 `time+duration` 限定姿势区间；`person.action.pose` 叠加姿势/注视而不重启动作相位。人物 `trajectory.set` 可传 `rotation/orientToPath/holdEndUntil`；重复点表示站位保持，不自动走路。省略新增字段保持原有命令行为。
- 路径、摄影机预设与动作区间替换继续共用 `stageRanges.ts`：保留区间外关键帧、1µs 保护帧、程序动作/片段相位与相邻平滑曲线。旧 orientToPath 的区间外朝向先采样为显式旋转，避免替换邻点改变原轨迹朝向。1µs 邻域不是无限精度的不连续曲线表示。
- `storyCompiler.test.ts`、`stageRanges.test.ts`、`stageDirect.test.ts` 和 `stageCommands.test.ts` 覆盖构图数学、切镜/融合边界、移动计时、目录错误、程序/片段相位、审批风险、批量原子性、回滚、一次撤销及读图草案验证。单测不等价于 UI/性能/录制或真实付费模型验收。

## 10. 我的模型库（GLB / GLTF，非 UI 核心）

### 10.1 持久化与导入边界

- `stage/domain/importedModel.ts` 定义 `ImportedModelAsset`：稳定 `id`、名称、原始文件名、标准 MIME、字节数、创建时间、`source: 'file'`、存储引用、原始轴向包围盒尺寸（米）、默认放置高度及可选 `upAxis: 'y' | 'z'`。默认遵循 glTF 的 Y-up / 米制约定，不猜测模型单位或上轴。
- 模型库索引复用资产库的 `createWorkspaceDocument` / workspace IndexedDB，键为 `storyboard-copilot:imported-models:v1`；提供新增、查询、列表、改名和删除。读取持久化数据时过滤损坏条目、去重 id，为缺失的旧可选字段补确定性默认值，拒绝未知的新版本。异步修改串行提交；未持久保存时导入报错，不宣称成功。
- 桌面端复用图片/视频的「应用数据目录 + 内容寻址文件 + Tauri command」机制：模型写入 `app_data_dir/models/<sha256>.glb|gltf`，`persist_model_binary` 使用原始二进制 IPC，临时文件同步后原子落盘，索引仅在字节保存后提交。`read_model_file` 支持用户选择的本地模型路径并在读取前检查大小。未将 GLB 冒充图片传给图片解码命令。
- 网页版 `npm run dev` 真实可用：`File` 的 Blob 字节复用资产 `media` object store 与 `asset-media:<mime>:<sha256>` 引用；不把大文件塞进 localStorage 或临时 blob URL。浏览器存储权限/容量不足明确失败；浏览器清站点数据会清除模型。网页版不能读取任意本地路径字符串，必须传入文件选择器得到的 `File`；桌面绝对路径引用也不能直接在网页版打开。
- 仅接受 glTF 2.0 `.glb` / `.gltf`，单文件上限 **100 MiB（104,857,600 字节）**，空文件拒绝。校验 GLB 的 `glTF` 标识、版本、长度及 JSON 块；GLTF 校验 UTF-8 JSON 与版本。外部 buffer / 纹理 URI 一律拒绝并给出中文重新导出提示；使用内嵌 GLB 或 data URI 的自包含 GLTF。加载器另有 URL 边界，不自动下载依赖。需要额外 Draco / KTX2 解码器的文件不承诺支持，解析失败明确报错。
- `importModelFile(fileOrPath, { name?, heightMeters?, upAxis? }?)` 只解析一次以测量原始尺寸；成功后把模板交给内存解析缓存。删除模型库条目不删除内容寻址字节、不修改画布节点或当前已加载实例；仍引用已删除 id 的节点下次加载明确报错，需要重新关联，不静默改成内置模型。

### 10.2 米制放置、缓存与资源所有权

- `loadImportedModel(assetId, heightMeters?)` / `resolveImportedModelMesh(item, heightM?)` 先按显式 Z-up 标记绕 X 轴旋转 −π/2，再测量包围盒。统一缩放 `s = 目标高度 / (maxY - minY)`，平移 `(-(minX+maxX)s/2, -minY*s, -(minZ+maxZ)s/2)`，使 X/Z 中心在原点、最低点在 Y=0、高度精确等于目标米数。未给高度使用资产默认高度，默认高度初始为原始轴向高度。无有效正高度的模型拒绝。
- 最外层 Group 保持单位变换，归一化发生在内部；既有 `pos3d / rotation3d / scale3d` 和动作轨只作用于外层，不会覆盖归一化偏移。`scale3d` 是用户后续额外缩放。导入模型启用 mesh 的投射/接收阴影，原始材质标记 `blueprintPreserveMaterialColor`，不被元素色自动重染；不自动播放 glTF 动画，不声称已有程序人物骨架与导入骨架兼容。
- 缓存按资产 id 单飞解析，保留最多 4 个 LRU 模板。每次放置通过 SkeletonUtils 克隆层级/骨架，再独立克隆 geometry、material、texture 的 GPU 句柄；纹理 CPU 像素源仅只读共享，不关闭共享 ImageBitmap。**导入实例不使用 `sharedResources` 标记**，可按现有场景 geometry/material 遍历释放；克隆材质的 dispose 监听器同时释放自己的纹理，克隆几何释放时清理其独立骨架。模板只由缓存驱逐/`clear()` 释放，不交给场景直接使用。`disposeImportedModelMesh(group)` 用于移除实例、丢弃过期异步结果和占位框；不对活模板调用它。独立纹理句柄有复制内存成本，换取与现有销毁遍历安全一致的所有权。

### 10.3 BlueprintScene 接线（本核心不改 React 组件）

1. 载入 `listImportedModels()` 元数据用于默认米制高度；`getItemHeight` 对 `importedModelId` 优先取资产 `defaultHeightMeters`，不能回落到内置 preset 高度。`getItemMeshCacheKey` 必须包含 `importedModelId` 与实际请求高度。
2. `createBlueprintItemMesh` 的首个分支处理 `importedModelId`，返回 `createImportedModelPlaceholder(heightM)`，优先于 person / preset 工厂；仍设置现有 itemId、cacheKey、baseRotation、baseScale。
3. Mesh-sync effect 在占位 Group 加入 `itemsGroupRef` / `meshByIdRef` 后调用 `resolveImportedModelMesh(item, heightM)`。保留占位外层 Group 作为变换目标，成功时释放并移除旧 wire-box 子节点，把返回的单位变换 Group 加为其子节点，重标所有 mesh 的 `name = item:<id>`，然后 `requestRender()`。只在视口仍挂载、`meshByIdRef.get(id)` 仍是该占位 Group、cacheKey 仍一致时采用结果；否则立即 `disposeImportedModelMesh(result)`。失败保留占位框并暴露实际错误，不自动重提交或伪装加载成功。
4. 重建/删除 item 以及 teardown 时，先 detach transform controls / 移出场景，再按已有几何/材质释放遍历处理导入实例（或调用 `disposeImportedModelMesh`）。只有已有姿势编辑器共享资源按其 `sharedResources` 标记跳过，导入模型不能跳过。缓存无需每次场景关闭都清空；应用退出或显式清缓存时 `importedModelParseCache.clear()`。

### 10.4 图像→3D：用户声明通道，不伪造供应商支持

非 UI 核心提供 `model.generate` 与独立 `kind: 'model'` 输出。它不代表某个供应商已经验收；没有新增服务预设、模型 ID 或猜测的 API。用户必须根据实际文档配置 endpoint、模板、图片槽位、参数、任务 ID / 状态 / GLB 或 GLTF URL 路径及认证策略。保留原有提交、轮询、结果请求和「未知提交绝不自动重发」规则。

1. `channels/domain/profile.ts` / Zod、响应解析、运行时输出、任务持久化及 Rust 快照校验明确接受 model；图片输入仍只接受 image 引用。`model.generate` 必须包含模型输出，可同时声明 image 预览。完整模式、`modeId` 和模式 endpoint 覆盖保留在不可变快照中。
2. `stage/application/imageTo3d.ts` 导出 `generateModelFromImage({channelModelRef,modeId?,imageRefs,params},{signal?,onProgress?}?)`，返回 `{importedModelId,previewAssetId?,jobId}`。`imageRefs` 为已有全局资产/画布图片 ID，或 `{assetId,slot?}`；多图片槽位必须显式分配。进度阶段为 submit / poll / download / import。不自动选择模型，也不修改舞台。
3. `useChannelModelGenerationCatalog()` 返回声明模型输出的模型及完整模式、`channelModelRef`、`usable/notReadyReason`。无凭据或无图片槽位明确不可用；只有用户配置的原生声明进入目录。
4. 桌面 `download_model_asset` 复用网络路由与凭据保险库，在响应 Content-Length 与流式累计两处限制 **104,857,600 字节**。下载可中断；拒绝重定向和凭据跨源，按 MIME / GLB glTF 标识 / glTF 2.0 JSON 校验，自包含资源以外全部拒绝，不自动抓取外部 buffer 或纹理。通过校验后原子保存内容寻址模型，再调用既有 `importModelFile` 解析和持久保存模型库索引。网页版同样限制流式大小，模型字节进入既有 IndexedDB 资产存储。
5. `recoverModelFromImage(jobId,options?)` 只查询/下载原任务，不需要重新提供参考图。模型以任务 ID + 输出序号形成稳定导入 ID，关闭发生在模型索引写入与任务结果写入之间也不会重复导入。成功结果保存 `kind:'model'`、`importedModelId`，不把临时 URL 当作已保存模型；下载失败保留原任务和安全结果引用以便重试下载。同步 base64 输出不会将大段原始数据写进恢复快照。
6. 取消会停止等待、轮询、模型下载及未提交的导入；已发送的提交不能承诺上游停止计费。保留返回错误中的 `jobId`，下次查询同一任务。`ModelDownloadError.code` 明确区分 too_large / invalid_model / network / canceled / storage。
7. Workbench 结果持久化保留模型 ID；采用和画布结果发布写入 `BlueprintItem.importedModelId`，创建真实模型舞台节点，不经过图片/音频存储或预览。UI 仍需接模型目录、配置入口、阶段进度、取消/恢复、结果采用与模型专用展示。真实供应商、付费调用和最终浏览器交互不属于本地夹具验证证据；验收前不宣称特定供应商「图像→3D 已支持」。
