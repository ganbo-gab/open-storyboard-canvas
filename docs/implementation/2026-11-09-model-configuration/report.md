# 模型配置一致性与旧代码清理

2026-11-09。用户提供的节点同时包含 `model=kie/nano-banana-2 / size=2K / aspectRatio=1:1` 与 `modelConfig.entryId=…gpt-image-2.6 / extraParams.size=1024x576`。Agent 因此误报模型和尺寸，等待框显示方形。源码修复后已按用户要求编译 0.2.2-preview.3 Mac arm64 验收包；未发布 GitHub Release，未替用户安装。包与校验记录位于仓库上级“验收包-2026-11-09-模型配置修复-preview3”。

## 根因

- `nodeRegistry` 新建图片、分镜节点时仍填入旧内置模型默认值 KIE 和 2K。该默认在历史提交 `0e9ddf7` 中已存在，并非用户新建了 KIE 渠道。
- 新 UI 写入 `modelConfig`，旧字段没有一起退出读取链；图片请求组装还先读旧内置模型并混合旧参数。
- `canvas.query` 原样脱敏返回两套字段，Agent 会误读；生成详情的技术记录反而只选旧 `model/size/aspectRatio` 展示，遗漏新的模型配置。
- 普通图片生成的结果补丁没有写比例，工厂给等待结果节点填了 `1:1`。这是实际展示错误，不能归咎于上游或 Agent 自己编造。
- 前端未知模型会回退 KIE；某些失效的保存选择会换成首个可用渠道。Rust 旧生成命令在无法解析模型时也会回退首个供应商。这些回退并非用户明确选择，存在配置与实际执行不一致风险。

## 修复

1. 新图片与分镜节点不再预填任何供应商模型和旧分辨率。已存旧字段保留兼容读取，但存在当前 `modelConfig` 时，以整份当前配置为准，缺少参数也不从另一旧模型借默认值。
2. 统一纯配置读取函数 `readGenerationConfiguration`，解析像素尺寸（1024×576 → 16:9），供 Agent 查询、审批概要、历史快照说明及当前图片节点提示使用。空生成器不暴露没有媒体依据的旧显示比例；真实结果节点的媒体比例保留。
3. 图片、分镜与工具面板组装读取实际渠道模式、参数和默认值。原生渠道未声明的尺寸不注入 2K。等待结果节点由本次组装请求写入模型、分辨率、比例和诊断上下文；未知比例保持自动。本地网格预览的显示比例使用自身实际绘制比例。
4. 新历史记录的模型以本次请求上下文优先；旧详情从该次记录的请求、持久任务和冻结节点快照解释，不用当前渠道或节点重写过去的生成事实。
5. 无效显式模型、失效的保存面板选择不再默换供应商。只有完全未配置时才提供首个可用选择。前端注册表未知 ID 不再返回 KIE；原生旧命令无法解析到供应商的模型在凭据绑定前报错。

## 全仓旧代码排查与清理

对前端静态导入、动态字面量导入、`import.meta.glob` 注册入口、测试与原生供应商分发进行了引用核查；没有把“文件旧”或“静态工具没看到”直接等同于无用。

已删除无运行入口、无测试消费者的内容，共约 1360 行：

- `ModelParamsControls.tsx`：旧内置图片参数界面，817 行。
- `CustomProvidersSection.tsx`：已被新渠道设置替代的旧入口，348 行。
- `EditorPopup.tsx`、`nodeControlStyles.ts`：未使用旧浮层和样式。
- `ModelConfigPicker` 中未使用的 `ModelConfigButton`。
- MultiAngle、Lighting、MultiFunction 中四个没有调用者的旧提示词辅助函数，活跃面板组件保留。

同时移除工厂 KIE/2K 注入、注册表默认 KIE 回退和原生默认供应商字段/访问器。现有内置供应商适配器与 Agnes 仍有显式旧配置、迁移、设置或注册表消费者，保留其兼容功能。Agent eval 虽非 UI 入口，仍有测试消费者，保留。不能据此声称仓库已不存在任何技术债。
