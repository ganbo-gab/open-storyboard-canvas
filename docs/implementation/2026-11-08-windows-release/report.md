# v0.2.0 发布前 Windows 原生回归

## 范围

发布目标为 Windows x64 NSIS 与 macOS Universal DMG。共享画布优化同时用于两端；此检查聚焦原生文件操作和打包，不是 Windows GUI 或帧率验收。

## 已定位问题

1. Node 22 / npm 10 的干净安装暴露锁文件缺少两项 peer 依赖记录，已补齐并通过两端 npm ci。
2. Windows 知识库的 Win32 重命名包装层与固定父目录句柄、单个文件名的调用方式不匹配。改用原生句柄相对重命名后，又发现目标父目录的共享权限冲突。
3. 专项 Windows 对照返回 `NTSTATUS=0xC0000043` / `Win32=32`；父目录只共享读取时失败，共享读写时成功。生产修复必须同时使用句柄相对访问，不能仅放宽权限后继续拼接路径。
4. 模型取消测试把目录项大小当作实时写入进度，Windows 下该元数据可在写句柄关闭前陈旧；改为读取实际文件前缀，已通过原生测试。
5. junction 测试夹具向 cmd 传入混合分隔符，被当作参数开关；改为原生分隔符并覆盖空格与 Unicode。超大附件夹具先关闭写句柄，再验证读取边界。

- 首次干净安装检查：GitHub Actions 42385222821。
- 首次原生检查：42385549459。Mac 218 项 Rust 测试通过；Windows 186 项通过、25 项失败。
- 修正协议及测试假设后：42388175407。Mac 全部检查与 Universal DMG 通过；Windows 188 项通过、25 项知识库测试失败。
- 目录共享专项：42390250518。原始系统错误及只读/读写对照确认共享冲突。

## 修复与专项结果

所有目录遍历、叶文件打开、目录与暂存创建现在通过 `NtCreateFile`，以固定父目录句柄和单个经过验证的文件名访问。目录允许内核重命名所需的写共享，仍拒绝删除共享；不再以拼接路径重新遍历祖先。保留 no-follow、长名匹配、UNC/设备/流路径拒绝和原子不覆盖提交。

Windows 专项 **42393352504** 已通过：**35 项知识库回归、12 项模型下载回归**。包含正常二进制读写、同名并发创建、回收与恢复冲突、8.3 别名拒绝、暂存清理；新增测试向已经打开的父目录注入 junction，绕过调用前检查直接验证底层打开、创建、跨目录替换不会触及外部哨兵文件。

测试夹具使用规范化长路径，匹配正式初始化入口；显式短别名拒绝测试仍保留。专项通过后还需由最终提交执行完整两端回归与打包，专项结果不能替代完整构建或 Windows GUI 验收。
