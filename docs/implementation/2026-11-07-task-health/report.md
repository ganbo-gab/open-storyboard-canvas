# 工作台异常任务识别与舞台特色说明

日期：2026-11-07。用户反馈前几天测试遗留的任务仍显示进行中，并要求把舞台 Agent 测试效果写入特色、明确实验阶段限制。

## 根因

工作台把 queued/submitting/running/materializing/unknown/recoverable_wait 六种状态全部算作进行中，未排除 waitingCanceled。实际上未知、待恢复、凭据暂停任务没有在自动查询，任务抽屉却仍累计自创建以来的秒数。真正 running 的任务还缺少长期无进展识别；轮询不断更新 updatedAt，不能拿该字段判断真实进度。

## 修复

- 拆分 running、attention 和 unresolved 选择器。运行数只包含四种执行状态且未暂停的任务；未知、待恢复、暂停任务进入待处理。已结束的失败历史不会全部塞进全局提示。
- 保留 unresolved 删除保护、原 jobId、上游句柄、请求与结果线索。没有把暂停当作取消/失败，没有自动重新提交，也没有直接改动用户保存的真实任务。
- 新任务保存本地观察窗口 startedAt/lastProgressAt；只有状态、阶段、节点、步骤或进度变化才刷新进展时间。反复返回相同状态、仅更新时间戳不会续期。
- 连续 6 小时没有观察到进展，暂停本地等待并标记待核对。旧记录用 createdAt 保守识别；重启、窗口重新聚焦、每分钟本地扫描及下一次自动查询前都会检查。该时限不是供应商超时，更不是上游失败判据。长队列/长生成也可能进入人工核对，显式恢复会重新打开观察窗口，只查询原任务。
- 暂停不会丢弃已经在途的返回：真正成功可保存结果，失败/取消显示最新终态；仍在运行的响应不会重新启动已暂停的本地查询。
- 任务中心分组显示进行中与待处理；暂停项显示绝对最后更新时间，不再持续计秒。细分凭据待授权、本地结果缺失、任务/结果未找到、长时间无进展。工作台卡片复用同一分类。抽屉顶部留出 36px 标题栏及间距，避免标题被裁切。
