# 凭据误锁与画布数量输入修复

> 后续用户验收发现换行布局不合要求，且 Mac 跨版本签名连续性未覆盖。已另行修正布局与发布签名流程；当前完整结论及尚缺证书见[验收更正](upgrade-followup.md)。本页原有测试结果仅覆盖当时范围。

日期：2026-11-09。基线：`next` / `00478b3`（v0.2.1 后发布工作流标题修正）。本轮为未发布源码修复，未替换用户安装的软件。

## 反馈与根因

1. **闲置后生成/查询报“系统凭据尚未授权”，重启恢复。** Rust 的凭据缓存用 15 分钟闲置时间（包含系统休眠、时钟回退）把已成功读取的条目转换成永久 `Blocked(storage_locked)`。这不是操作系统撤销权限；它跨 Mac、Windows 生效，只有显式重新授权或进程重启能解除。所有存储错误也被同样永久缓存。
2. **Windows 与 Mac 的临时故障被误报为权限问题。** 锁定依赖 `windows-native-keyring-store 1.1.0` 中 `NoStorageAccess` 唯一来源是 `ERROR_NO_SUCH_LOGON_SESSION (1312)`，即登录会话不可用；此前应用统一当作授权拒绝。已核对官方 crate 源码与 Cargo.lock 的 SHA256。Mac 的 `errSecNotAvailable (-25291)` 也被归错。前端随后抹掉具体错误码，并对缺失、校验失败、暂不可用全部显示“未授权”。Windows 的存在性检查还会绕过成功读取的缓存。
3. **长模型名隐藏右侧数量。** 参数条全部禁止收缩，超过宽度后用隐藏滚动条的横向滚动承载，导致数量被推出可见范围。
4. **参数里的数量被忽略。** ImageEditNode 的独立局部数量默认是 1，每次提交都作为显式 count 覆盖渠道参数里的 n。还有参数已声明但未映射到提交模板时被错误识别为“原生批量”的问题。

## 修复行为

- 已读凭据在原生进程内复用，不再凭应用闲置时间制造授权过期。删除、替换、显式重试仍更新对应缓存；值不会进入公开 React 状态或普通配置文件。
- 已知缓存状态用于存在性检查。仅确认条目存在不等于获得密码读取权限。
- 临时存储失败不再永久黏住，下次调用可恢复；Mac 确认拒绝/取消仍阻止后续自动读取，须用户明确重试。写入回读不一致仍阻断，不能偷偷回退旧密钥。Windows 不透明的其他平台错误仍阻止请求；不通过字符串猜测系统错误码。
- 前端保留经过白名单校验的错误码，分别提示缺少 Key、真实拒绝、保存校验失败与临时读取失败；成功存在性检查可以清除暂时错误，但不能抹除真实拒绝或写入校验失败。健康的凭据字段不再一直显示“重新授权”。
- 恢复按钮改为“重试读取凭据”，有上游任务时再查询原结果；没有上游任务时只恢复凭据，明确告诉用户此前未提交，不自动生成。恢复凭据之后的查询故障不会再次错误归咎于授权。
- 参数面板和右侧 ×N 共用当前模式参数。更换模式/自动文生图与图生图切换时使用对应数量限制；历史 count 不再覆盖用户新改的原生数量。自定义渠道只有提交请求确实映射了数量参数才被视为原生批量；否则仍通过外层批量提交。旧模型的生成/编辑接口按实际参考素材分别判断，避免请求数相乘。
- 模型/参数格最大 180px，长文字省略且模型原有完整名称 title 保留；参数空间不足时换行。数量与发送位于独立固定区域，不随参数横向溢出。新增图引用订阅仅在选中节点或打开请求预览时挂载。

没有新增全局“开机授权”，没有提权或绕过系统权限，也没有自动重试付费提交。旧版明文配置与目前系统凭据库的差异可在 credentialMigration 的迁移代码中确认；改用安全存储本身不应导致周期性授权。
