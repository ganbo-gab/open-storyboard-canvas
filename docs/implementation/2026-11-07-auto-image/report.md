# 图片模式自动识别

日期：2026-11-07。用户要求图片创作默认根据有无参考图自动选择文生图/图片编辑，减少手动选择。

## 行为

- 明确声明图片模式的渠道，新选择模型默认「自动识别」；无图选唯一可用文生图，有图优先选唯一可容纳图片的编辑模式。若供应商同一个image.generate接口也接收参考图，可以继续用其声明，不能凭空发image.edit。
- 工作台上传、拖入/资产引用共用addReferences逻辑；先纳入图片再解析模式、分配单一图片槽。移除最后一张图回文生图。旧草稿/历史中明确保存的模式ID继续尊重，菜单可重新选择自动。
- 画布图片节点读取当前图输入，模式与参数面板同步。自动切换保留新模式仍有效的参数，其他采用新默认；手动模式的无效参数仍严格拒绝。多图角色、多个候选模式、超过容量时要求手动选择/分配，不按模式名字猜角色。未成功分配的素材保持可见，不能悄悄丢弃。
- 实际提交前在共用解析器中确定模式，再投影参数、数量与图片槽；网关预览和执行共用。explicit空referenceSlots={}继续表示明确空输入，不被generic图片覆盖。mixed image/video模式不从参考图数量猜用途。
- 工作台提交记录与画布统一历史保存实际modeId；画布复用同时保存有效提交参数。原任务恢复仍使用已保存job，配置变化不触发新生成。
- 修正画布重新点击同一手动模式时清空参考槽的问题，手动模式间切换保留兼容槽位；新选择模型清理旧mode/槽位避免串模型。
- 分镜网格与图片工具走同一图片提交解析；native模式使用自身声明参数，避免把旧2K/auto几何提示硬塞进pixel枚举。分镜网格本身是一张参考图，其模式提示计入该图。
